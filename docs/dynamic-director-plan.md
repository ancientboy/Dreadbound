# Dreadbound：动态副本与 AI 导演路线

## 设计目标

Dreadbound 不应只依赖固定路线、固定触发器和固定敌人位置。目标是让每次行动都保留手工设计的恐怖节奏，同时让房间连接、任务条件、敌人压力、事件因果和奖励选择根据本局种子与玩家行为发生变化。

这里的“AI 特色”不等于在浏览器中强制调用在线大模型。核心系统应首先使用**可复现的程序化生成、效用评分、规则推理和行为记忆**，保证离线可玩、低延迟、可测试和存档稳定；生成式模型可作为开发期内容生产工具，或未来作为玩家明确选择的可选叙事层。

## 为什么不能直接把整张地图完全随机化

完全随机的房间和任务容易产生：

- 无法完成的任务条件；
- 钥匙、供电和出口互相锁死；
- 敌人堵门或出生围杀；
- 恐怖节奏消失，连续多个空房或连续高压战斗；
- 小地图、迷雾、Boss 和撤离逻辑难以验证；
- 玩家失败时无法判断是决策问题还是生成器恶意。

因此采用“**手工模块 + 约束生成 + AI 导演**”三层结构，而不是无规则随机 Tile。

## 一、动态地图：手工房间图重组

### 房间模块

每个房间仍由设计者制作，但带有结构化标签：

- 入口方向和门连接点；
- 房间类型：安全、探索、战斗、资源、事件、任务、Boss、撤离；
- 最低/最高敌人压力；
- 可放置任务物、资源、事件和伏击的插槽；
- 可见性、照明、电力和迷雾参数；
- 所属主题与允许出现的灾难世界。

### 生成流程

1. 根据行动种子选择地图规模和主线骨架。
2. 先放入口、主任务节点、供电、Boss 区和出口，确保关键路径必定连通。
3. 在关键路径之间插入 2～4 个可选房间。
4. 添加一条回环路线，避免所有行动都是单向走廊。
5. 将资源和安全房放在高压房间前后，而不是完全均匀随机。
6. 运行可达性、门连接、任务顺序和撤离验证。
7. 验证失败时丢弃该布局，并使用同一种子派生新的尝试编号。

第一版不是无限地图，而是准备约 12～16 个疗养院房间模块，每局选择 7～10 个组成副本。这样既能改变路线，又能保持每个房间的手工质量。

## 二、动态主线与支线任务契约

任务不再直接写死为“永远找三份记录”，而使用 `MissionContract`：

- 前置条件；
- 目标类型；
- 目标数量范围；
- 合法房间标签；
- 中途变体；
- 成功、部分成功和失败条件；
- 对后续事件、Boss、撤离和奖励的影响。

### 疗养院候选主线

1. **档案回收**：找到 2～4 份记录，再恢复电力。
2. **样本封存**：取得污染样本，必须选择净化或带回。
3. **幸存者信号**：追踪信号源，可能找到幸存者、诱饵或已异化目标。
4. **异常切除**：关闭分布在不同区域的节点，关闭顺序会改变敌人行为。

### 支线触发条件

支线由条件组合触发，而不是固定进入某房间即触发：

- 玩家携带特定装备或消耗品；
- 当前生命、弹药或污染状态达到阈值；
- 先前选择了某个风险事件；
- 在限定时间内进入某类房间；
- 没有杀死某类敌人，或连续击杀过多敌人；
- 携带来自上一灾难世界的物品；
- 终末回廊中的某项强化或档案已经解锁；
- 本局种子选中了特定因果链。

同一个支线至少准备两个入口条件和两个结果变体。例如“回响病房”可能因为携带镇静线圈而安全进入，也可能因为使用兴奋剂而触发更强伏击。

## 三、AI 导演：根据玩家行为编排压力

新增本地 `DreadDirector`，持续读取但不修改玩家输入：

- 当前生命和补给；
- 最近 90 秒受到的伤害；
- 弹药消耗速度；
- 连续战斗时间；
- 未探索房间数量；
- 玩家是否经常逃跑、潜行或清图；
- 已完成任务与风险事件；
- 当前行动耗时和撤离距离。

导演维护三个主要指标：

1. **压力**：敌人、黑暗、资源不足和追击带来的紧张程度。
2. **节奏债务**：连续高压后应提供喘息，连续安全后应逐步制造威胁。
3. **机会值**：玩家当前是否需要获得补给、捷径、情报或高风险奖励。

导演只能从合法候选中选择内容，例如：

- 下一未探索房间是资源房、伏击房还是事件房；
- 是否延迟一波敌人，让低生命玩家先找到逃生路线；
- 是否将高价值支线与额外敌人绑定；
- Boss 追击阶段选择封锁哪条非唯一通路；
- 是否触发一次环境声、灯光异常或假信号。

导演不允许暗中修改命中率、凭空扣血、读取玩家未来输入或在唯一出口生成不可绕过的敌人。

## 四、敌人记忆与群体行为

让敌人表现出“观察玩家”的特点，而不需要在线模型：

- Patient 记住最后看见玩家的位置，并搜索邻近房间。
- Crawler 根据玩家常走的通道选择侧翼入口。
- Orderly 优先封锁玩家近期多次使用的门口，但不能封锁唯一出口。
- 同一房间的敌人共享一次有限警报，而不是所有敌人全图同步追踪。
- 玩家频繁使用枪械会提高后续房间警觉度；持续近战则可能增加重型敌人权重。

这些记忆只在本局存在，撤离结算可以用一句话总结导演观察到的行为倾向，例如“本次行动表现：高噪声、强搜集倾向、低撤离意愿”。

## 五、因果链：让选择跨房间产生后果

每局生成 1～2 条隐藏因果链：

```text
污染药柜选择强行开启
→ 孢子计数提高
→ 后续病房照明出现异常
→ 某个 Patient 变体获得毒性攻击
→ 击败后可能得到净化样本
→ 撤离结算解锁特殊档案
```

因果链必须在结果发生前提供至少一个可感知线索，避免玩家觉得系统在无理由惩罚。展开地图和任务日志应记录已发现的因果线索，但不提前公布全部结果。

## 六、动态奖励与装备适配

奖励不完全独立随机，而参考本局构筑：

- 三个 Boss 候选中至少一个与当前武器相关；
- 至少一个候选解决当前资源短板；
- 第三个候选可以是高风险异常装备；
- 连续多局没有获得新装备类别时，提高缺失类别权重；
- 不保证出现直接升级，保留横向取舍。

导演只调整候选权重，不直接把指定最强装备送给玩家。所有候选仍由行动种子决定并在生成后固定。

## 七、生成种子与可复现性

每局保存：

- 基础种子；
- 地图生成尝试编号；
- 房间模块顺序；
- 主线与支线契约；
- 因果链；
- Boss 奖励候选；
- 导演的重要决策日志。

用途：

- 玩家可分享“行动代码”；
- 测试人员可以准确复现死路或不公平遭遇；
- 每日挑战可以让所有玩家使用相同基础布局；
- 存档恢复不会刷新任务或奖励；
- 自动化测试可以批量验证数百个种子。

## 八、生成式 AI 的合理使用

### 开发阶段

生成式 AI 可辅助：

- 为任务契约生成文案变体草案；
- 为房间模块提出事件组合；
- 生成终端日志、病历和环境叙事初稿；
- 分析批量模拟结果，寻找过难种子；
- 为固定数据生成测试案例。

所有正式内容仍需人工审核、统一世界观并打包进游戏。

### 运行时可选层

未来可以提供明确的可选功能：玩家主动启用后，由在线模型根据已发生的结构化事件生成行动报告或终末回廊评语。该功能必须：

- 默认关闭；
- 不影响掉落、数值和通关条件；
- 明确说明网络、隐私和可能产生的费用；
- 在线服务不可用时完整游戏仍能运行；
- 不发送玩家身份或无关设备信息。

首个正式版本不依赖运行时大模型，以保证手机 Web 性能、离线可玩和长期可维护性。

## 九、分阶段实施

### 阶段 H1：动态框架

- 将疗养院拆成 12～16 个房间模块。
- 建立带种子的房间图生成器和任务插槽。
- 加入可达性、关键路径、门连接和撤离验证。
- 支持显示行动种子和开发者重放。

### 阶段 H2：任务与因果

- 实现 2 个主线契约、4 个支线契约和 3 条因果链。
- 支线使用组合条件和多个结局。
- 任务日志显示已知线索和结果。

### 阶段 H3：AI 导演

- 建立压力、节奏债务和机会值。
- 动态选择房间内容、敌人组合、喘息与高风险机会。
- 加入敌人有限记忆、噪声和房间级警报。

### 阶段 H4：验证与扩展

- 自动运行至少 500 个种子，禁止死路、缺失目标和不可撤离布局。
- 比较不同玩家风格的完成率、平均时长与资源曲线。
- 手机和 iPad 验证生成耗时、内存与 WebGL 稳定性。
- 框架稳定后，第二个灾难世界只需提供自己的房间模块、契约、因果链和导演候选。

## 自动化门槛

动态系统进入 Web 发布前必须满足：

- 同一种子和相同决策产生相同初始地图、任务和奖励。
- 每个生成地图都有入口到主任务、供电/Boss 和出口的合法路径。
- 关键物品不会生成在需要该物品才能进入的区域。
- 唯一出口和唯一任务节点不会被永久封锁。
- 500 个测试种子全部可完成，生成时间和内存峰值在移动 Web 预算内。
- 导演决策有调试日志，可以说明“为何生成此事件”，避免不可解释的暗箱调整。

## 下一项实际开发任务

不立即制作大量新地图素材。先实现 H1 的技术原型：

1. 定义 `RoomModule`、连接点和内容插槽数据；
2. 从现有疗养院切出 8 个最小房间模块；
3. 用种子生成一条必通主路径和一条可选回环；
4. 随机分配三份记录、供电、Boss 和出口，但保证任务顺序合法；
5. 小地图和迷雾改为读取生成后的房间图；
6. 增加种子显示、复现入口和批量生成测试。

完成 H1 后，再逐步把现有风险事件改造成动态支线契约，而不是一次性推翻当前可玩版本。
