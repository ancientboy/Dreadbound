# O0：Playable Alpha 统一基线

状态：**已锁定**  
基线：N0–N7 世界与叙事、V21 掉落与回廊、两张持续副本  
下一阶段：O1 正式美术资产

## 1. Alpha 的一句话目标

让第一次接触 Dreadbound 的玩家不依赖开发者解释，也能在一分钟内理解“进入灾难世界—调查/战斗—承担选择—撤离—带回成长—世界记住结果”的循环，并愿意主动开始第二次行动。

O 系列不再以“代码中已有按钮或数据”为完成标准，而以玩家能看到、听懂、操作并得到反馈为完成标准。

## 2. 核心受众与承诺

- 喜欢恐怖生存、撤离压力、Roguelite 构筑与持续叙事的玩家。
- 单人优先，10–15 分钟一局；未来的 2–4 人协作不能破坏单人体验。
- 选择会影响 NPC、路线、档案、物品和再次进入时的世界状态。
- 装备成长可以规划：成本、路径、条件和后果都在选择前可见。
- 正式内容保持原创，不复用现有影视/小说副本或辨识度过高的外壳。

## 3. Alpha 必须成立的体验

### 第 1 分钟

- 首页无乱码，世界观卖点和“进入终末回廊”主入口清晰可见。
- 新玩家知道这是一款俯视角恐怖生存撤离游戏，而不是纯文字档案。
- 桌面和手机横屏均能建立/选择档案并开始。

### 第一局

- 通过环境与短提示学会移动、攻击、切换武器、拾取、交互和撤离。
- 玩家始终知道当前主目标、可选风险与撤离条件。
- 首次危险、首次掉落、Boss 预兆、死亡和撤离都有清晰视听反馈。
- 不要求玩家先读完世界档案才能理解任务。

### 局外成长

- 装备、材料、唯一藏品、职业、副本、档案与终端七个入口可辨识。
- 强化/进化/合成在确认前显示所需数量、当前持有、输出候选和路径。
- 玩家能解释“下一局为什么要回去”，并能找到对应入口。

### 第二次进入

- 至少一项 NPC、路线、章节、广播、敌人或奖励变化明确源自上一局选择。
- 行动档案能指出因果来源，不能只显示抽象数值变化。

## 4. 平台与性能预算

| 项目 | Alpha 门槛 |
|---|---|
| 桌面 Web | 1280×720 基准，主流 Chromium 浏览器可完整游玩 |
| 移动 Web | 960×720 与常见手机横屏无按钮遮挡、无关键内容越界 |
| 帧率 | 目标 60 fps；中端移动设备高压战斗不持续低于 30 fps |
| 首次下载 | O1/O2 完成后 Web 发布包建议不超过 80 MB |
| 单场景纹理 | 建议不超过 2048×2048 atlas；大型背景拆层/按场景加载 |
| 同时声音 | 常态不超过 24 voices，高压场景不超过 32 |
| 存档 | 旧存档继续迁移；资产替换不得改变结算事实 |

## 6. O1–O6 顺序与出口

| 阶段 | 交付 | 退出条件 |
|---|---|---|
| O1 正式美术 | 首页 Key Art、回廊、两世界 Tile/Prop、玩家、敌人/Boss、图标、核心 VFX | 所有 P0/P1 美术资产在三种 viewport 可读；不再依赖程序形状表达核心角色/物品 |
| O2 音频氛围 | 音乐、环境、战斗、敌人、UI、广播 | 两世界可凭声音区分；关键预兆与操作有反馈；混音和循环通过 Web 真机测试 |
| O3 新手与 UI | 首局剧情教学、任务路线、操作反馈、设置、移动端 | 5 名未看文档测试者中至少 4 名能独立完成首次目标或准确说明失败原因 |
| O4 战斗经济 | 敌人、武器、掉率、成本、进化速度、局长 | 10–15 分钟目标成立；无单一装备/路线在大多数测试中垄断选择 |
| O5 数据试玩 | 匿名行动统计、死亡/撤离/卡点、反馈入口 | 获得 10–20 名玩家的两局以上数据，并形成有证据的调整清单 |
| O6 发布能力 | Windows、云存档服务、版本/反馈、正式试玩页 | Web/Windows 同版本；云存档可关闭回退；发布说明与隐私边界完整 |

不在 O1 之前开发第三张大型副本；第三副本与完整多人由 O5 的真实数据决定。

## 7. 资产优先级

- **P0**：首页入口、玩家、终末回廊、两世界基础 Tile、普通敌人、两个 Boss、基础武器/材料图标、关键战斗与撤离声音。
- **P1**：完整 Prop、所有装备/藏品图标、进化形态、世界环境层、敌人声纹、UI 反馈。
- **P2**：稀有变体、档案插画、装饰动画、宣传扩展，不阻断核心玩法。

O1 的第一批不是批量生成全部素材，而是制作一个“风格试片包”：

1. 行者四方向 idle/walk。
2. 终末回廊一块 8×8 Tile 试片与入口 Prop。
3. 病患 idle/walk/attack。
4. 疗养院一间标准病房。
5. 首页 Key Art 构图草案。

该试片在游戏内通过尺寸、轮廓、色板、动画与移动端可读性后，再批量扩展。

## 8. 发布门禁

- `content/alpha_asset_manifest.json` 结构、唯一 ID、规格和必需覆盖由自动测试检查。
- 外部素材没有明确许可证与来源记录时，CI/人工审查不得批准。
- `approved` 资产的目标文件必须存在、可导入并符合尺寸/格式；O0 阶段所有待生产项保持 `planned`。
- 每次 O1/O2 提交同时更新清单和授权台账。
- 任何正式资产替换都必须运行完整 Godot 测试、Web 导出及真实手机横屏烟雾测试。
