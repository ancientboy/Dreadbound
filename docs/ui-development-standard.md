# Dreadbound UI 开发与验收标准

本标准适用于终末回廊和所有灾难世界。第二地图不得复制第一地图后再自行调整一套坐标；两张地图必须共享 `main.tscn` 的 HUD、弹窗、移动控制和小地图。

## 布局约束

- 1280×720 是设计基准，不是可用画布永远固定为该尺寸的假设。
- 顶部 HUD、弹窗和底部操作必须依据当前 viewport 重排，并保留至少 14 px 安全边距。
- 状态文字不得互相覆盖；低优先级电脑快捷键可在窄画布隐藏，任务、生命和进度不可隐藏。
- 弹窗必须相对 viewport 居中，宽度不得超过画布减去 64 px。
- 终末回廊终端的子项总最小宽度不得大于父容器；新增按钮时必须同步检查总宽度。
- 手机触控热区之间不得重叠，并应与浏览器底部安全区保持距离。

## 复用约束

- 新灾难世界只提供世界配置、房间、任务、敌人和主题表现，不得复制 HUD 场景。
- 通知、风险事件、结算、Boss 奖励和完整地图必须使用共享面板。
- 修改共享 UI 后必须同时回归疗养院、潮没末班线和终末回廊。

## 发布门禁

每次发布前至少检查 1280×720、1024×768 和 960×720 三种 viewport：

1. 顶部文字无交叠、无越界；
2. 通知、风险事件、结算与奖励弹窗均在安全区域内；
3. 小地图和移动按钮不遮挡任务导航；
4. 回廊终端左右内容及底部按钮完整可见；
5. 两张地图使用完全相同的共享 UI 行为。
