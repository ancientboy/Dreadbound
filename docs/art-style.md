# Dreadbound：正式美术制作标准（O0 锁定）

本文件是 Dreadbound 从灰盒进入 Playable Alpha 后的唯一美术基线。概念图可以探索，但所有进入游戏的 Sprite、Tile、图标、特效和宣传画面都必须回到本标准整理。任何偏离都需要先修改本文件与 `content/alpha_asset_manifest.json`，不能在单个素材中临时决定。

## 1. 视觉命题

**写实人体比例的低分辨率俯视恐怖像素画。**

- 冷峻、脏旧、克制，恐怖来自空间、轮廓、声音与等待，不依赖满屏血浆。
- 终末回廊是“无法确认年代的异常基础设施”，不是霓虹赛博酒吧。
- 灾难世界保留真实公共设施的功能痕迹，再由异常规则侵蚀。
- 战斗信息优先于装饰：敌人轮廓、攻击预兆、可交互物和撤离方向必须可读。
- 禁止 Q 版大头、彩色手游质感、光滑 3D 转像素、随机混用不同像素密度。

## 2. 固定技术规格

| 项目 | 锁定值 |
|---|---|
| 设计画布 | 1280×720 |
| 世界网格 | 32×32 px Tile |
| 标准人形单帧 | 48×64 px |
| 大型人形/Boss 单帧 | 96×96 px；超高 Boss 可用 96×128 px |
| 地面型小怪单帧 | 64×48 px |
| 装备/材料图标 | 32×32 px 原始像素；UI 可整数倍显示 |
| 方向 | Down / Left / Right / Up，固定行序 |
| 纹理过滤 | Nearest；禁止双线性缩放 |
| 缩放 | 游戏内优先整数倍；不得用缩放修正不同素材比例 |
| 色彩空间 | sRGB，PNG 透明背景 |

标准玩家脚底锚点为 `(24, 58)`；碰撞只覆盖脚下约 22×18 px，不按整个人形计算。人形武器、手电筒光照、阴影与命中特效保持独立层，避免每换一件武器就重画完整角色。

## 3. 统一镜头与像素语言

- 使用俯视 3/4 视角：能看到人物正面/背面与少量物体顶部，不采用纯侧视或等距 45°。
- 一个世界中的边缘厚度、门高、床宽、轨道宽度和角色脚底比例必须来自 32 px 网格。
- 单个角色建议不超过 24 个可见颜色；单个世界 Tile/Prop 套装建议不超过 48 个主颜色。
- 像素边缘必须手工清理；禁止抗锯齿、半透明脏边和不受控的抖动纹理。
- 角色阴影为独立低透明椭圆层；环境主光与手电筒由 Godot 实时光照承担，不烘焙进所有 Sprite。

## 4. 锁定色彩

| 语义 | 色值 | 用途 |
|---|---|---|
| Void | `#0B0F14` | 深层背景、不可进入区域 |
| Slate | `#182129` | 面板、阴影、墙体基色 |
| Iron | `#2B343B` | 金属、边界和中间层 |
| Bone | `#C9C2AE` | 主要文字、旧纸、苍白皮肤高光 |
| Anomaly Cyan | `#59E1E6` | 回廊、可交互异常、主入口 |
| Sick Green | `#7D9B76` | 疗养院灯光、药品、腐败 |
| Rust | `#8A5147` | 锈蚀、旧血、危险环境 |
| Hazard Amber | `#D0845A` | 攻击预兆、倒计时、资源风险 |
| Dried Blood | `#6E2C35` | 伤害与血迹，禁止大面积纯红 |
| Archive Violet | `#A79ACB` | 真相、记忆与档案层 |

每个灾难世界最多新增 2 个主强调色。异常青色只表达“回廊/异常可交互”，不能同时承担普通装饰，否则玩家会失去信息判断。

## 5. 动画字典

### 玩家

| 动画 | 每方向帧数 | 建议速率 |
|---|---:|---:|
| idle | 4 | 5 fps |
| walk | 6 | 9 fps |
| melee_attack | 6 | 12 fps |
| ranged_attack | 4 | 12 fps |
| hurt | 3 | 10 fps |
| interact | 4 | 8 fps |
| death | 8 | 10 fps，不循环 |

### 普通人形敌人

`idle 4 / walk 6 / attack 6 / hurt 3 / death 6`。特殊攻击可增加 6–8 帧，但攻击预兆必须至少持续 0.35 秒并拥有独立轮廓变化。

### Boss

`idle 6 / move 8 / attack_a 8 / attack_b 10 / phase_change 12 / hurt 4 / death 12`。Boss 的阶段变化优先通过轮廓、动作与声音表达，不能只换颜色。

所有 Sprite Sheet 使用：

- 行：Down、Left、Right、Up。
- 列：按时间从左到右。
- 文件名：`<asset_id>_<animation>_<frame-width>x<frame-height>.png`。
- 同类动画不得在导入后依靠不规则裁切修复画布。

## 6. 世界差异

### 终末回廊

玄武岩般的深色结构、旧工业设备、磨损黄铜与异常青光。空间应该“干净但无法理解”，避免堆满废品。主入口、档案、装备、材料、藏品、职业、副本与终端必须各有稳定轮廓图标。

### 废弃疗养院

病态绿、骨白瓷砖、暗锈红、旧木与氧化金属。核心图形语言是“被制度反复覆盖的姓名”：病历标签、缝线、床号、删改痕迹。

### 潮没末班线

湿冷蓝灰、信号琥珀、污水黑与褪色交通标识。核心图形语言是“仍在运行的失效秩序”：时刻表、检票孔、导轨、淹没刻度。

## 7. 角色识别

- **行者**：约 30 岁、中性外观、灰绿色旧夹克、黑色工装裤、棕色靴；宽肩夹克、背包、手电筒和左腕青光是缩小显示时的识别点。
- **病患**：破损病号服、迟缓重心、靠近后突然扑击。
- **爬行者**：四肢异常拉长、贴地高速移动，以低矮轮廓区分。
- **护理员**：高大旧制服、布条覆面，缓慢但占据更宽攻击区。
- **缝合主任**：多个被制度缝成一个职责的人形，镰与病历缝线共同构成轮廓。
- **溺行者**：被水压拖拽的乘客轮廓，移动时留下短暂水迹。
- **检票员**：制服与闸机结构融合，抬臂就是明确拦截预兆。
- **车长回声**：由车长制服、信号灯和轨道电弧构成，不做普通巨型人类。

## 8. UI 与图标

- UI 保持异常设施监控终端风格，正文不叠加噪点、扫描线或色差。
- 32×32 图标先保证 1× 可读，再允许 2×/3× 整数显示。
- 装备轮廓代表功能；品质只改变边框/微光，不能用颜色代替形状。
- 材料图标必须同时表现世界来源与材料类别。
- 首页 Key Art 不直接作为游戏地图贴图；它可以更细致，但必须使用同一角色、色板和世界建筑语言。
- 手机触控图标须在 48 px 热区内保持至少 24 px 的清晰主体。

## 9. 生产与验收流程

1. 黑白轮廓稿：确认尺寸、识别与攻击预兆。
2. 基础色：只用锁定色板和世界附加色。
3. 动画试片：先完成 Down/Left 两向，放进 1280×720 真机画面验证。
4. 全方向与分层：通过试片后扩展，不提前批量制作。
5. Godot 导入：Nearest、正确锚点、碰撞盒与动画名。
6. 三场景验收：终末回廊、疗养院、末班线都不得出现风格跳变。
7. 登记来源：原创/生成/外部素材都写入 `docs/asset-license-ledger.md`。

AI 图像生成只用于原创概念探索和基础素材生产。生成结果必须重新整理像素密度、调色板、分层、透明边缘和逐帧连续性后才算“可进游戏资产”。
