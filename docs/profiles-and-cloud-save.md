# 多行者档案与云存档

## 本地优先

每个浏览器最多创建 6 个昵称档案，每个档案写入独立 `user://dreadbound_<profile_id>.json`。旧的 `dreadbound_progress.json` 首次启动时自动导入为“旧档行者”。未配置云服务时，创建、改名、选择、删除、游玩和结算都不依赖网络。

## 因果里程碑

- 首次完成废弃疗养院：1 因果残片。
- 首次击败缝合主任并撤离：1 因果残片。
- 首次完成潮没末班线：2 因果残片。
- 首次击败末班列车并撤离：1 因果残片。

已领取 ID 与货币在同一存档事务中写入，重复结算、刷新和重进不会再次领取；结算终端显示每项来源。

## 可选云服务

参考实现位于 `backend/`，提供注册、登录、读取、条件写入和账号删除。客户端只保存短期 bearer token，不包含管理员密钥；服务器只保存 token 哈希，密码使用 PBKDF2-HMAC-SHA256。部署后在 `project.godot` 设置：

```ini
[cloud]
api_url="https://your-cloud-save.example.com"
```

服务未配置或不可用时，请求会失败但本地档案保持可玩。云写入携带期望 `revision`；版本不一致时玩家明确选择保留本地或采用云端，禁止静默覆盖。游客注册/登录后可以把当前档案作为 revision 0 上传，实现本地档案绑定；删除云账号不会擅自删除本地档案。

生产部署必须启用 HTTPS、速率限制、邮箱验证、数据库备份、监控、隐私说明和外部密钥管理。
