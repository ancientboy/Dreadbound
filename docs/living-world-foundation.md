# 持续世界底座

阶段 J0 把长期世界逻辑从具体地图场景和结算汇总中拆出，建立后续人性回声、阵营模拟、异步社会和实时多人共同使用的数据边界。

## 行动事件账本

`ActionLedger` 使用一套统一结构记录关键行为：

- `event_id`：由 `run_id + sequence` 确定，可用于幂等处理。
- `run_id` / `action_code`：关联一次可复现行动。
- `profile_id`：关联本地玩家档案。
- `world_id` / `content_version`：标明内容与迁移边界。
- `event_type` / `actor` / `target` / `choice`：描述发生了什么。
- `context` / `result`：保存行为发生时的信息和已确认结果。

当前已经接入 `run_started`、`risk_choice` 和 `run_settled`。新玩法应调用 `GameState.record_action()`，不再自行维护另一套历史格式。

账本在单档中最多保留 512 条事件；每局结算快照会写入 `last_run.action_events`，供回廊战报与后续司仪系统读取。

## 持续世界状态

`WorldStateStore` 独立保存：

- 世界周期。
- 四方阵营的影响力、补给和玩家信任。
- 区域控制、安全度、污染度和资源。
- NPC 长期状态插槽。
- 最近世界事件。
- 已处理事件 ID。

地图只读取和呈现这些状态，不拥有长期世界事实。第一版在每局结算时推进一个世界周期，保持低成本、确定性和浏览器兼容性。

## 因果规则

`ConsequenceEngine` 只接受结构化事件，并通过 `processed_event_ids` 保证同一事件最多生效一次。相同初始状态与相同事件序列必须得到相同结果。

当前首批规则验证了完整通路：

- 冒险/保守风险选择会改变区域污染与共鸣体信任。
- 守诺/背弃事件会改变漂泊者信任和区域安全。
- 成功撤离/行动失联会改变区域安全、消耗资源并推进世界周期。

AI 司仪可以选择、预测和解释候选规则，但不得绕过规则引擎直接修改世界数值。

## 存档兼容

J0 首次引入 v16；J1–J6 集成后当前存档版本为 v17。加载 v16、v15 或更早存档时：

- 原有成长、装备、档案、里程碑和司仪试炼保持不变。
- 缺少行动账本时创建空账本。
- 缺少持续世界状态时创建默认阵营和区域状态。
- 新字段会在下一次正常保存时写入。

自动化测试覆盖事件顺序、因果结果、重复结算、保存恢复和旧档迁移。
