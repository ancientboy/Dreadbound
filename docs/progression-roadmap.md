# Dreadbound：局外成长与内容扩展路线

## 方向决策

下一阶段不立即制作第二张灾难地图，而是先补齐**终末回廊 → 疗养院 → 撤离结算 → 终末回廊**的完整循环。当前疗养院已经能够验证移动、探索、任务、战斗和撤离，但撤离后的奖励没有真正进入可持续成长系统；此时扩张新地图只会复制一个尚未闭环的结构。

“主神空间”属于其他作品常用的辨识性表达，不作为本项目名称。Dreadbound 使用原创设施 **终末回廊**：它既是行者整备与强化的局外空间，也是展示人物变化、任务档案和世界观的叙事界面。

## 下一阶段：终末回廊最小闭环

本阶段只制作一个可操作的灰盒大厅和必要界面，不扩张为复杂基地经营。

### 1. 撤离结算

- 疗养院成功撤离后进入结算页，而不是直接停留在关卡中。
- 统计本局找到的记录、回响碎片、弹药与补给、击败的敌人和事件结果。
- 区分“可带回资源”和“仅限本局资源”；失败时按明确规则损失本局战利品。
- 玩家确认结算后返回终末回廊。

### 2. 角色档案

- 显示生命上限、移动速度、近战伤害、手枪伤害、绷带效率等基础属性。
- 显示当前持有的回响碎片、因果残片和已解锁强化。
- 属性数值必须来自统一数据模型，不能只写在 UI 文本中。

### 3. 永久强化

首轮只实现 4 项清晰、可测试的永久强化：

1. **耐受训练**：提高生命上限。
2. **神经校准**：提高移动速度。
3. **武器适配**：提高近战与手枪基础伤害。
4. **应急处理**：提高绷带恢复量。

强化消耗回响碎片，购买后立即更新角色档案，并在下一次进入疗养院时生效。因果残片先进入账户但暂不开放消费，避免过早引入复杂能力树。

### 4. 整备与再次出发

- 提供简化整备界面，查看下一次出发携带的武器和基础补给。
- 第一版使用有限的预设配置，不做网格式背包、重量系统或大量随机词条。
- 从终末回廊选择“进入疗养院”后重新开始一局，并保留永久成长。

### 5. 存档

- 使用 Godot `FileAccess` 保存局外货币、强化等级和设置。
- Web 版依赖浏览器持久化存储；提供“清除存档”入口用于测试。
- 存档需要版本号和缺省值，以便后续字段增加时安全迁移。

## 后续阶段顺序

1. **风险事件**：在疗养院加入两种事件，验证继续深入与立即撤离的收益权衡。
2. **疗养院内容补齐**：The Orderly、简单 Boss、第三种武器和剩余消耗品。
3. **表现与平衡**：灯光、音效、统一像素素材、移动端 Web 性能与 10～15 分钟节奏。
4. **第二个灾难世界**：只有首个循环稳定后才立项；复用结算、成长、整备和存档系统，而不是复制临时代码。

## 完成标准

- 玩家能从终末回廊出发，完成或失败一局，看到准确结算并返回。
- 成功带回的回响碎片可以购买强化，重进疗养院后属性确实变化。
- 刷新 Web 页面后，合法的局外进度仍然存在。
- 没有通过反复刷新、重复结算或失败流程无限领取奖励的漏洞。
- 手机横屏下可以完成结算、强化、整备和再次出发，不依赖键盘。

## 暂不实现

- 第二张地图、程序化关卡和地图随机拼接。
- 大型装备仓库、装备耐久、复杂词条与制作系统。
- 多角色队伍、基地建设、NPC 日程或联网同步。
- 完整人性异化树；本阶段只为其预留数据位置和界面入口。
